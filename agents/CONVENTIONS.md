# Conventions and invariants

## Hard invariants (each one was a real bug or a deliberate design decision)

1. **libtorrent headers stay in `torrent_manager.cpp` / `torrent_metainfo.cpp`.**
   `manager.h` is a pimpl so the rest of the code never pays the libtorrent + boost
   compile cost. Don't expose `lt::` types in public headers.
2. **No hand-rolled BitTorrent.** An earlier version faked progress and had a broken
   SHA-1/bencode parser. Use `lt::parse_magnet_uri` / `lt::load_torrent_file`.
   The empty `torrent_{dht,peer,piece,tracker,…}` scaffolds were deleted on
   purpose; don't recreate them.
3. **libtorrent 2.x with `deprfun` disabled** has no `torrent_info::files()` or
   `trackers()`. Use `layout()` and `add_torrent_params::trackers` instead.
4. **All HTTP goes through `idr::network::HttpClient`.** No `curl_easy_*` calls in
   `download.cpp`.
5. **`MyApp::OnInitCmdLine` must keep declaring the optional `url` positional param.**
   Without it, wx rejects `idr://…` and aborts `OnInit()` silently.
6. **Never write unvalidated bytes.** Ranged responses go through a
   `ResponseValidator` (206 + exact `Content-Range`). Single-stream output opens
   lazily after validation.
7. **Never mark Completed without checking the size on disk** against the expected total.
8. **Engine threads are owned and joined**, never detached. Stop → `WaitForWorker()`
   before deleting a download's files.
9. **Status callbacks must not take `DownloadManager::m_mutex`** (deadlock: the manager
   holds it while calling `Pause()`, which notifies). The DB is guarded by `m_dbMutex`.
10. **The `DownloadStatus` integer values are persisted.** Append new states; never renumber.
11. **Segment layout is derived from existing `.partN` files** when they exist. Don't
    recompute it from settings on resume, or the parts get corrupted.
12. **App data lives in `system::AppDataDir()`**, never the CWD. `idr://` launches
    inherit the browser's working directory.
13. **Android's vcpkg triplet stays at API 24** (`android/vcpkg-triplets/arm64-android.cmake`).
14. **The six browser copies must not drift.** Edit `browser/chrome/` first, then copy
    the change to the others. CI checks that they match.

## Don't touch without asking the owner

- `core/tests/*` and `plugins/` — reserved directories; keep them.
- `core/src/utils/database/database.h` — intentionally unused placeholder.
- `site/AGENTS.md` — regenerated by `next dev`; edit only outside its marker block.
- The non-commercial `LICENSE`.

## C++ style (`core/`, Android native)

- C++17. Namespaces `idr::<area>` (`download`, `network`, `torrent`, `model`,
  `system`, `utils`).
- Prefer `std::error_code` overloads of `std::filesystem` in engine code. Exceptions
  are caught at thread boundaries (`Download::Run`).
- Write `(std::max)(a, b)` / `(std::min)(…)` in any file that may include
  `<windows.h>` (through curl or wx), or the Windows `max`/`min` macros break the build.
- Getters that the GUI calls are atomics or mutex-protected copies. The GUI never
  blocks on network I/O.
- Log through `idr::system::Log()` (spdlog fmt syntax: `"{}"`). Use info for
  lifecycle events, warn for retries, and error for failures.
- New `.cpp` files are picked up by `file(GLOB_RECURSE)`. Re-run CMake configure
  after adding or removing files.
- Build with `/W4` and keep the project's own code warning-free.

## JavaScript (`browser/`)

- Vanilla JS, no build step, MV3. Use `chrome.*` callback APIs (Firefox and Safari
  provide them as shims).
- Check `chrome.runtime.lastError` in callbacks that can fail.

## Commits

- Conventional prefixes (`feat:`, `fix:`, `docs:`, `refactor:`, `ci:`).
- Prefer a feature branch + PR into `main` for anything beyond a one-line fix.
